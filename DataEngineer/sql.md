# Тестовое задание

Создайте таблицу для incremental-загрузки `shipments` (поставки).

Источник данных - таблица `raw.shipments`. Содержит только актуальные записи о поставках. Записи как добавляются в источник, так и редактируются и удаляются.

## Поля источника

- номер поставки `ship_order`
- дата поставки
- статус поставки
- номер клиента
- номер SKU - уникальный код товара `sku`
- количество
- стоимость в рублях
- дата изменения информации в текущей строке (`changed_at`)
- дата загрузки в данную таблицу (`loaded_at`)

## Требования для incremental-таблицы и процессу её наполнения

- одна строка = одна комбинация `ship_order + sku`
- загружать только новые и изменённые записи
- корректно обрабатывать повторные загрузки и дубли
- использовать `changed_at` как watermark для incremental-загрузки
- при одинаковом `changed_at` использовать `loaded_at`

## Необходимо

- написать DDL для таблицы `shipments`
- написать SQL-логику загрузки:
  - через MERGE, если СУБД поддерживает
  - или через DELETE + INSERT
  - или другим обоснованным способом
- кратко описать выбранную incremental-логику и подход к дедупликации
- Написать SQL-запросы, которые проверяют:
  - нет дублей по ship_order + sku
  - нет NULL в ключевых полях
    - quantity > 0
    - amount >= 0
  - в целевой таблице хранится актуальная версия записи

## Опционально

При желании добавить дополнительное представление (view) с полезной аналитикой.

## Ограничения

- СУБД значение не имеет (желательно классическую реляционную, но не критично)
- Набор тестовых данных (raw.shipments) - заполнить на своё усмотрение для возможности демонстрации
- Можете выдвигать свои предположения, какого рода и качества данные могут быть, и закладывать это в проект (предполагаем, что работаем в условиях недостатка информации / прототипирования)
